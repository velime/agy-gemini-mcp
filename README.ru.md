# agy-gemini-mcp

[English version](README.md)

MCP-сервер, который позволяет Claude Code поручать работу Gemini через Antigravity CLI (`agy`) по
подписке Google AI Pro, без API-ключа. Claude здесь начальник: он ставит задачу, читает результат
Gemini и присылает правки. Тяжёлую работу (написать код, нарисовать картинку) делает Gemini, поэтому
лимиты Claude уходят в основном на проверку.

Проект не связан с Google и Anthropic. Перед использованием прочитайте раздел «Риски».

## Почему Antigravity CLI, а не Gemini CLI

18 июня 2026 Google перестал обслуживать Gemini CLI для личных аккаунтов, включая Google AI Pro
([обсуждение](https://github.com/google-gemini/gemini-cli/discussions/28017),
[заметка](https://9to5google.com/2026/06/17/gemini-cli-code-assist-shutting-down/)). Замена называется
Antigravity CLI, бинарник `agy`. Он входит через Google-аккаунт и имеет
[неинтерактивный режим](https://antigravity.google/docs/cli/headless/) (`agy -p "..."`), через который
и работает этот сервер.

## Установка

1. Установите Antigravity CLI с [antigravity.google](https://antigravity.google/).
2. Нужен Google-аккаунт с подпиской Google AI Pro.
3. Один раз запустите `agy` в терминале и войдите в этот аккаунт.

### Регионы, где Antigravity недоступен

Antigravity доступен не во всех странах. Мы столкнулись с двумя отдельными проверками: локальной
внутри `agy` («not currently available in your location») и серверной по IP-адресу, где Google
отвечает `User location is not supported for the API use` (HTTP 400). В нашем тесте снятия локальной
проверки оказалось недостаточно: серверный ответ не менялся, пока не сменили сетевой выход в интернет.
Другие пользователи пишут, что причиной бывают: трафик Google, исключённый из туннеля VPN, DNS-серверы
местного провайдера и VPN-серверы, которые Google считает адресами дата-центров
([Meduza](https://meduza.io/en/news/2026/08/14/gemini-s-vpn-workaround-stops-working-for-some-users-in-russia),
[обсуждение на Хабре](https://habr.com/en/articles/1017738)); это отдельные свидетельства, не
гарантии. Какую страну видит Google, можно проверить из того же терминала, где запускается `agy`:
`curl https://ipinfo.io/country`.

Для пользователей из России: локальную проверку внутри `agy` убирают сторонние патчеры
([QNIX-Dev/eligibility-antigravity-patcher](https://github.com/QNIX-Dev/eligibility-antigravity-patcher),
исходники на Python в репозитории, и
[open-antigravity-patcher на SourceForge](https://sourceforge.net/projects/open-antigravity-patcher/)).
Проверено на практике: без патча `agy` в России не запускался (`Eligibility check failed`), а одного
патча недостаточно: серверная проверка идёт по IP-адресу, и патч её не снимает. Часть серверов (VPN и
подобных сервисов) Google банит, поэтому придётся искать свой рабочий вариант. Автору помог вот этот
сервис: <https://t.me/oversecureone_bot>; автор проверил его на практике, и с ним всё заработало. Но
безопасность и репутацию сервиса мы не проверяли, а любой такой сервис видит ваш трафик.
Порядок такой: установить Antigravity CLI, применить патч, найти рабочий сетевой выход и войти в
аккаунт в `agy`. Аудит исходного кода
патчеров мы не проводили. Оба правят бинарники Antigravity и читают сохранённые токены входа, а автор
одного из них сам пишет, что это может нарушать условия использования. Прочитайте исходники до запуска;
запуск на свой риск, лучше с запасным аккаунтом, который не жалко потерять.

Патч слетает при автообновлении. У нас так и случилось: `agy` сам обновился с 1.4.2 до 1.4.3,
заменил пропатченный `agy.exe` новым, и следующая задача сразу упала с
`Eligibility check failed ... not currently available in your location` (старые версии остаются рядом
как `agy.exe.*.old` и `agy.exe.agybak`). После обновления патч нужно применить заново, и он должен
поддерживать новую версию. Чтобы обновления не ломали патч, отключите автообновление переменной
окружения `AGY_CLI_DISABLE_AUTO_UPDATE=true`
([страница устранения неполадок Antigravity](https://www.antigravity.google/docs/cli/troubleshooting)).
Сервер при такой ошибке возвращает её в `agy_error`, и скиллы в этом случае останавливаются, а не
повторяют запросы.

### Установка сервера

```bash
git clone https://github.com/velime/agy-gemini-mcp
cd agy-gemini-mcp
npm install
claude mcp add --scope local agy -- node /абсолютный/путь/к/agy-gemini-mcp/server.mjs
```

`--scope local` включает сервер только в текущем проекте. Чтобы включить везде, используйте
`--scope user`. После этого перезапустите Claude Code. Проверка, что всё работает от начала до конца
(делает два небольших реальных запроса к Gemini):

```bash
node selftest.mjs
```

По желанию скопируйте `skills/gemini-code` и `skills/gemini-image-loop` в `.claude/skills/` вашего
проекта (или в `~/.claude/skills/`), чтобы получить работу с кодом и картинками, описанную ниже.

Настройки (переменные окружения): `AGY_PATH` (путь к бинарнику `agy`, на Windows находится
автоматически), `AGY_WORK_ROOT` (единственная папка, где Gemini разрешено работать, по умолчанию
`~/gemini-work`).

## Как это устроено внутри

Три инструмента:

- `agy_run(prompt, workdir, conversation_id?, model?, effort?, mode?, timeout_min?)` запускает задачу в
  Gemini и сразу возвращает `job_id`.
- `agy_result(job_id, wait_s?)` ждёт до 45 секунд и возвращает статус, ответ Gemini, `conversation_id` и
  расход токенов, либо `state: running`, если он ещё работает.
- `agy_cancel(job_id)` останавливает задачу.

Важные детали:

- Каждая задача запускает `agy --output-format json --dangerously-skip-permissions -p "<prompt>"` с
  рабочей папкой в качестве текущей. Задачи асинхронные, потому что задача Gemini идёт минуты.
- Вывод `agy` пишется в файл, а не в канал (pipe). По сообщению сторонних авторов, на Windows режим
  печати `agy` может ничего не вернуть, если stdout это pipe
  ([gist](https://gist.github.com/allahsan/a9a9e9c8a49aecede67ce974e64ef3cf)), а ошибки квоты могут
  выглядеть как успех. Сервер считает «код выхода 0, но JSON нет» ошибкой.
- Если передать `conversation_id` из результата в следующий `agy_run`, Gemini продолжит ту же сессию.
  Так работают правки: Gemini помнит, что он сделал.
- Промпты длиннее 6000 символов записываются в `TASK.md` в рабочей папке из-за ограничения длины
  командной строки Windows.
- Рабочая папка должна лежать внутри `AGY_WORK_ROOT`. Это защита от ошибок, а не песочница: `agy`
  работает с автоподтверждением, поэтому Gemini в принципе может выполнить команды, затрагивающие
  другие места.
- Задачи хранятся только в памяти; перезапуск сервера забывает работающие задачи.

Живая картина того, что делает Gemini: `tools/watch_agy.py` читает журнал шагов самого `agy` (только
чтение) и печатает по строке на каждый шаг по мере появления (команды, записанные файлы, вызовы
субагентов, ошибки API):

```bash
python tools/watch_agy.py
```

В приложении Claude скиллы открывают её сами во вкладке Терминала «Gemini live», так что вы видите, что
делает Gemini, не выходя из Claude. Скрипт следит за последним активным диалогом (`--conversation ID`
выбирает конкретный, `--from-start` печатает и прежние шаги).

## Gemini для кода, Claude как проверяющий

Это делает скилл `gemini-code`, и сначала он оценивает размер работы: мелкие правки Claude делает сам
(делегирование стоило бы дороже самой правки), небольшие задачи уходят коротким прямым ТЗ с
`effort: low` (от секунд до 2 минут), средние и крупные получают полное ТЗ, больше времени и
предупреждение пользователю (около 15 минут для задачи на 500 строк). Без скилла дайте Claude такую
инструкцию (или положите её в `CLAUDE.md`):

> Для больших задач по коду не пиши код сам. Делегируй через инструменты `agy`: напиши ТЗ с конкретными
> критериями приёмки, запусти его через `agy_run` в папке внутри рабочего корня, прочитай результат и
> файлы, которые создал Gemini, запусти тесты и присылай точные правки в тот же диалог через
> `conversation_id`. Остановись после 5 раундов и отчитайся.

Когда это выгодно: крупная работа с большим объёмом написания (новые модули, много файлов, шаблонный
код, тесты). Claude тратит токены на ТЗ и проверку, а не на генерацию сотен строк. Это оценка, а не
замер: примерно в 2–4 раза меньше расход Claude на таких задачах.
Когда невыгодно: мелкие правки в одном-двух файлах. Написать ТЗ, подождать несколько минут и
прочитать ответ дороже, чем просто сделать.

Расход на стороне Gemini по нашим запускам: большая первая задача (инструмент на 550 строк с тестами)
заняла 14 минут и около 420 тысяч токенов; маленькая задача с узкой формулировкой (инструмент на 54
строки с тестами) заняла 27 секунд и 57 тысяч токенов; правка в том же диалоге от 40 секунд до 2
минут. Узкое место теперь ваша квота Google, поэтому формулируйте задачи узко.

Почему задачи бывают медленными (определено по журналу шагов самого agy,
`~/.gemini/antigravity-cli/conversations`):
- Исследования и черновые скрипты. Если ТЗ к этому подталкивает («сверься с реальным HTML», «будь
  точен»), агент запускает десятки экспериментов. В задаче на 550 строк это 31 скрипт на Python и 35
  чтений и записей файлов. Просите работу напрямую: «пиши файлы сразу, не исследуй, без черновых
  файлов, запусти тесты один раз».
- Долгая генерация. Большие файлы с «думающей» моделью пишутся медленно (в той задаче 33 тысячи токенов
  размышлений). `effort: low` убирает почти все размышления.
- Сбои API. В той задаче 300 секунд из 966 ушли на один «stream idle timeout (5m0s)» и автоматический
  повтор. Задача при этом заканчивается, поэтому возможен статус `ERROR` при полном ответе. Сервер
  возвращает причину в `agy_error`. С нашей стороны это не предотвратить, это сервис. В ранних
  задачах похожая потеря была из-за ошибки `INTERNAL (code 500)`.

Gemini работает в папке внутри рабочего корня. Чтобы он правил настоящий проект, скопируйте проект в
эту папку и после проверки перенесите результат обратно, либо задайте `AGY_WORK_ROOT` на папку, где
лежат ваши проекты (рискованнее из-за автоподтверждения).

## Картинки: Gemini рисует, Claude руководит

Gemini генерирует картинки внутри `agy` встроенным генератором, без API-ключа (мы проверили:
красное яблоко на белом фоне, кружка с надписью). Следовать ТЗ он умеет плохо:

- текст внутри картинки часто неверный или искажённый;
- количество объектов и запреты вроде «не рисуй X» часто игнорируются;
- любая правка перерисовывает всю картинку. На просьбу только перекрасить кружку из синей в красную он
  заодно поменял фон и комнату.

Поэтому Claude работает как арт-директор (скилл `gemini-image-loop`). Он превращает ваш запрос на любом
языке в чек-лист и английский промпт, понятный Gemini: суть остаётся вашей, но детали уточняются
(предмет, кадр, свет, фон, чего не должно быть). Промпт уходит в Gemini, Claude сам смотрит PNG и
сверяет его с чек-листом. Там, где картинка неверная, Claude переписывает промпт именно в этих местах
(больше деталей, яснее формулировка, остальное без изменений) и отправляет обновлённый промпт целиком.
До 5 итераций; после 3 неудачных попыток подряд он останавливается и спрашивает вас. Когда Claude
считает картинку правильной, он показывает её вам и спрашивает, всё ли верно. Каждый просмотр картинки
расходует часть лимита Claude, поэтому есть потолок.

Скорость: промпты должны быть короткими. Одну и ту же правку фото мы замерили дважды. Длинный промпт с
требованием оставить всё остальное «точно» таким же заставил агента Gemini выполнить 42 шага на
Python/Pillow (палитра, разница массивов, склейка) и занял больше 9 минут. Короткий промпт со словами
«используй только свой инструмент генерации картинок, не используй Python и библиотеки для изображений»
занял 79 секунд и около четверти токенов. Скилл написан с учётом этого.

Тот же цикл правит готовое фото. Gemini видит только файлы в своей рабочей папке, поэтому Claude
копирует туда ваше фото как `input.png` (фото, прикреплённое в чате Claude, клиент сохраняет в файл, путь
к которому Claude видит; фото из папки копируется оттуда; оригинал не трогается), сам смотрит его и
пишет промпт: что оставить и что изменить. Мы проверили: на фото яблока Gemini добавил ленточку на
черешок, а яблоко, лист, фон, кадр и свет остались как были.

## Турнирный скилл (по желанию)

Если нужно, чтобы несколько Gemini-конкурентов атаковали ответы друг друга и выбирали лучший, смотрите
отдельный репозиторий [gemini-arena-skill](https://github.com/velime/gemini-arena-skill). Он дорогой по
квоте Gemini, поэтому ставится отдельно и по желанию.

## Риски

- Условия использования. Использование Antigravity из региона, где он не предлагается, или по подписке,
  купленной не у Google, может нарушать условия Google. Аккаунт могут ограничить или заблокировать.
  Используйте аккаунт, который не жалко потерять.
- `--dangerously-skip-permissions` означает, что Gemini может выполнять команды без вопросов. Держите
  `AGY_WORK_ROOT` подальше от важного.
- Квота: интенсивное использование может исчерпать дневной лимит Google. Сервер сообщает об ошибках
  квоты, а не повторяет запросы.
- Всё предоставляется «как есть», без гарантий.
